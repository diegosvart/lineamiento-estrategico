# Memoria — Intake admin

## Objetivo

Definir el punto único de entrada para nuevas necesidades del sistema y reducir decisiones dispersas entre ramas.

## Dueño

- Rama: `workspace/planning`
- Rol: admin + planning

## Qué entra por admin

- bloqueos actuales
- mejoras futuras
- cambios de contrato
- cambios de entorno
- dependencias entre ramas
- follow-ups detectados por un ejecutor

## Clasificación oficial

Toda necesidad debe caer en uno de estos tipos:

| Tipo | Qué significa | Destino habitual |
|------|---------------|------------------|
| `bloqueante actual` | detiene trabajo activo o una entrega inmediata | plan inmediato o handoff urgente |
| `mejora futura` | mejora útil, pero no bloquea el flujo actual | backlog |
| `cambio de contrato o entorno` | altera reglas, responsabilidades, configuración o estándares | memoria + guía + distribución por ramas |

## Resolución mínima del admin

El admin debe convertir cada necesidad en exactamente uno de estos resultados:

- `plan`
- `handoff`
- `backlog`
- `observacion`

## Regla para el humano

El humano informa la necesidad en lenguaje simple. El admin la transforma al formato operativo del sistema.

## Regla para ejecutores

Los ejecutores pueden detectar necesidades, pero no convertirlas por sí solos en estándar permanente.
